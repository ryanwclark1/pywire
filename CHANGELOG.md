# Changelog

Entries are maintained with each version change.

## 0.42.0 — pgwire 0.42 migration

### Upstream

- Wrap pgwire 0.42.3, pyo3 0.30 and pyo3-async-runtimes 0.30. This picks up
  pgwire's fix for GHSA-95f6-gpr7-g65r (plaintext sent between `SSLRequest`
  and the TLS handshake is no longer carried across the upgrade), stricter
  SCRAM validation, per-connection auth state, and errors instead of panics
  on truncated frames.

### Added

- `pywire.errors.InvalidMessageLength`, `TruncatedMessage` (both
  `ProtocolError`) and `NoAuthenticationInProgress` (`AuthError`), mirroring
  the new upstream `PgWireError` variants.
- `LoginInfo.sni_server_name` and `LoginInfo.client_certificates` (DER, leaf
  first) from pgwire 0.42's TLS client info.
- `TLSConfig.client_ca`: require and verify client certificates (mutual TLS).
- `pywire.sync.serve_forever` accepts every option `serve` does.
- `raise pywire.errors.UserError(ErrorInfo(...))` sends that error with its own
  SQLSTATE and fields from any handler (query, extended query, COPY, auth),
  instead of the generic `XX000`.
- COPY support: `Response.copy_in(handler, columns=...)` starts `COPY ... FROM
  STDIN` and delivers data to a `pywire.copy.CopyHandler`
  (`on_copy_data` / `on_copy_done` / `on_copy_fail`, mirroring pgwire's
  trait); `Response.copy_out(chunks, columns=...)` streams an async iterable
  of `bytes` for `COPY ... TO STDOUT`. Text, CSV and binary formats. A
  client `CopyFail` is answered like PostgreSQL does (SQLSTATE 57014,
  `COPY from stdin failed: ...`), which drivers such as psycopg rely on to
  re-raise the application's own exception. A `copy_in` must be the last
  response `do_query` returns (pgwire sends the list without pausing for
  COPY data); otherwise the client gets SQLSTATE 0A000.
- 29 more `pywire.messages` codecs, each with `encode` / `decode`, equality,
  hashing and Hypothesis round-trip tests: the extended-query protocol
  (`Parse`, `Bind`, `Describe`, `Execute`, `Close`, `Sync`, `Flush`,
  `ParseComplete`, `BindComplete`, `CloseComplete`, `ParameterDescription`,
  `NoData`, `PortalSuspended`, `EmptyQueryResponse`), COPY (`CopyData`,
  `CopyDone`, `CopyFail`, `CopyInResponse`, `CopyOutResponse`), startup and
  auth (`SslRequest`, `Authentication`, `PasswordMessage`,
  `SASLInitialResponse`, `SASLResponse`, `ParameterStatus`, `BackendKeyData`,
  `CancelRequest`) and `NoticeResponse` / `NotificationResponse`.
- `pywire.types`: `Type`, an `IntEnum` of every built-in PostgreSQL type OID
  known to `postgres-types` (generated by `scripts/gen_types.py` and
  checked against the build), and `Format.TEXT` / `Format.BINARY`. Both are
  re-exported as `pywire.Type` and `pywire.Format`.

### Documentation

- New project logo and brand palette for the docs site and README.
- A user guide covering simple queries, types and formats, prepared
  statements, sessions, streaming, COPY, errors, authentication, TLS, server
  lifecycle, wire messages, testing and typing, plus a rewritten quickstart.
- Ten runnable examples in `examples/`, included verbatim by the guide and
  executed by the test suite.

### Typing

- One source of truth for types: the duplicate `pywire/*.pyi` stubs are gone,
  so mypy now checks the real modules, and the native extension is described
  by a complete stub package in `pywire/_pywire/`.
- Stubs match the runtime exactly (`mypy.stubtest` reports no errors, down
  from 176): native classes are `@final`, constructors are typed as
  `__new__`, attributes are read-only properties, and `TransactionStatus` is
  no longer misdescribed as an `enum.Enum`.
- New `pywire.query.ResponseKind` literal type for `Response.kind`.
- New `pywire.session` module with `SimpleQuerySession`, `ExtendedQuerySession`
  and `ClosableSession` protocols. `SessionFactory` is generic: write
  `SessionFactory[MySession]` (strict checkers now require the type argument).
- `pywire.server.AuthMethod` names the accepted `auth_method` values.
- Dataclass list fields no longer appear as `list[Unknown]` to pyright.
- CI runs stubtest and pyright (strict) alongside mypy.

### Changed

- **Breaking:** `pywire.copy` is reshaped to pgwire's model now that COPY
  is wired up: `CopyInfo` and the `start_copy_in` / `start_copy_out` /
  `next_copy_out_chunk` callbacks (never connected to the server) are
  removed, and `on_copy_done` returns the row count.
- `Response.stream` accepts any async iterable (it previously required an
  async iterator), and rejects non-iterables with `TypeError` up front.
- Frozen value classes (`FieldInfo`, `LoginInfo`, `Password`, every message
  codec, `FieldDescription` and `TransactionStatus`) are now hashable,
  consistent with their equality.
- The stored-verifier SCRAM handler rejects a non-empty `a=` authorization
  identity, matching pgwire 0.42 and PostgreSQL.

## 0.41.0 — pgwire 0.41 migration

- Wrap pgwire 0.41.0, including PostgreSQL-compatible empty prepared statements.
- Preserve custom parameter type OIDs and reuse each bound Python portal through

## 0.40.0 — Initial bindings

pywire `X.Y` mirrors pgwire `X.Y`; this release wraps
[`pgwire 0.40`](https://crates.io/crates/pgwire/0.40.0). See
[`VERSIONING.md`](VERSIONING.md) for the policy.

### Binding surface

- **`pywire.errors`** — every `PgWireError` variant mirrored as a
  Python exception under a three-level hierarchy (root `Error`,
  umbrellas `ProtocolError` / `AuthError`, then 33 concrete classes).
  `ErrorInfo` carries PostgreSQL's standard error-field set
  (severity, code, message, plus 15 optional metadata fields).
- **`pywire.messages`** — wire codecs for `Startup`, `Query`,
  `Terminate`, `ReadyForQuery`, `CommandComplete`, `RowDescription`
  (+ `FieldDescription`), `DataRow`, and `ErrorResponse`. Each class
  has `.encode()` and `.decode(bytes)` and round-trips with
  bit-for-bit fidelity. `TransactionStatus` enum for `ReadyForQuery`.
  Extended-query / COPY / handshake-extras messages remain for a
  follow-up.
- **`pywire.auth`** — `LoginInfo`, `Password`, and the
  `AuthSource` async ABC. Plus an internal Rust adapter so future
  startup handlers can call into Python auth policy.
- **`pywire.query`** — `SimpleQueryHandler` async ABC with the full
  `Response` tagged union (`empty()`, `execution()`, `query()`,
  `error()`). `ExtendedQueryHandler` ABC plus `PreparedStatement` /
  `Portal` / describe-response dataclasses for forward-compat.
  `FieldInfo` for column metadata.
- **`pywire.copy`** — `CopyHandler` async ABC for both `COPY FROM
  STDIN` and `COPY TO STDOUT` flows.
- **`pywire.server`** — `pywire.server.serve(simple_query, addr)`
  binds a TCP listener and runs the simple-query path end-to-end.
  Per-connection tokio tasks; multiple concurrent clients
  supported. No auth, no extended query, no COPY, no TLS at this
  release; all four planned for v0.40.1.
- **`pywire.sync`** — `serve_forever(handler, addr)` wraps the async
  server in `asyncio.run` for CLIs and one-off scripts.

### Infrastructure

- CI across Ubuntu, macOS, and Windows with cargo fmt/clippy, ruff,
  mypy strict, cargo-deny, and actionlint.
- Tagged verification and wheel-build workflow for Linux, macOS, and Windows.
- Coverage gate: **100% effective line coverage** on hand-written
  code, with pyo3 macro decoration and explicit `// LCOV_EXCL_LINE`
  defensive-path markers exempted. Codecov for PR-level visibility.
- Docs site at https://ryanwclark1.github.io/pywire/ (MkDocs Material
  + mkdocstrings).
- Conventional Commits are used for change history.
